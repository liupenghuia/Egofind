# Task: 乘客地图点司机标记—行程摘要与确认后电话

## Origin

- Source idea: `None` — 产品负责人直接下发，无需独立 discovery brief。
- Promotion decision/evidence: 用户 `顺序完成` 指令（2026-07-20）。
- Pipeline modifiers: **只要小程序**；**UI 需我确认**（UI 相位后暂停）。

## Goal

乘客在小程序地图上点选「车找人」司机标记后，能**清楚看到行程摘要**，并在**确认同行之后**才能获取并拨打司机电话；确认前不得暴露可拨号能力。

## Users And Assumptions

- Primary user: 乘客模式用户（已登录；理想情况已发人找车）。
- Assumptions:
  - 后端已有 markers / 行程详情 / confirm / contact-phone 能力（MVP 已实现骨架）。
  - 「看清摘要」主要靠小程序信息架构与状态呈现；必要时后端可补字段（由 Architect 判定）。
- External dependencies: 微信小程序、电话能力 `makePhoneCall`；真机/DevTools 为人工门禁。

## UI Design

- Spec path: `docs/ui/specs/map-driver-summary-confirm-call.md`
- Spec status: `Ready for Review`（等待用户确认）
- Command sequence: Product ✓ → UI Design ✓ → **[暂停确认]** → Architect → Backend/Mini-App → Test

## Scope

**In scope**

- 乘客模式：地图标记点击 → 行程摘要（路线、时间、余座、分摊价等可读信息）。
- 摘要进入详情后的主路径：确认同行 → 再显示/启用拨号。
- 确认前：不可拨号；拨号入口禁用或隐藏，并有短说明。
- 司机模式：点标记仅查看（人找车），**无**拨号入口（保持非对称）。
- 仅 **miniprogram**；不改管理后台。

**Out of scope**

- 管理端、支付、IM、实时轨迹、强制派单。
- 司机主动联系乘客。
- 微信 DevTools / 真机自动化验收。

## User Stories

- As a 乘客, I want 点地图上的司机标记后立刻看懂这趟车去哪、何时、有无座、大概分摊, so that 我能决定是否确认同行。
- As a 乘客, I want 只有确认同行后才能打司机电话, so that 减少误触与骚扰、符合平台安全默认。
- As a 司机, I want 不被乘客在未确认前看到可拨号入口, so that 联系权保持非对称。

## Acceptance Criteria

- [ ] 乘客模式、同区县有车找人标记时：点击标记可看到**可读行程摘要**（至少：起终点名称、出发时间窗或开始时间、余座；有价则展示分摊价）。不把「裸 adcode」当主信息。
- [ ] 从摘要可进入完整详情；详情中「确认同行」仅乘客可见且可点（满员/不可接时禁用并说明）。
- [ ] **确认前**：乘客看不到可用的「拨打司机电话」主操作（隐藏或明确禁用 + 文案「确认同行后可联系」）；调用 contact-phone 失败时有可读错误，不崩溃。
- [ ] **确认后**：出现可点的联系/拨号；成功后可调起系统拨号（真机门禁单独记录）。
- [ ] 司机模式：地图点乘客标记无拨号入口；文案不暗示可打电话。
- [ ] 未发布人找车就确认：有明确引导（去发布），不静默失败。
- [ ] Loading / 空标记 / 请求失败有可见状态。
- [ ] 服务端仍强制：仅乘客、仅 CONFIRMED/COMPLETED 可取电话（客户端隐藏不算安全完成）。

## Architecture Impact

- Architecture: 待 Architect（UI 确认后）— 评估摘要层用 markers 字段 vs 详情接口；确认后 matchOrderId 持久/回读。
- API: 可能微调 markers/详情/my matches 的展示字段；安全规则不放宽。
- Database/migration: 预期 None 或仅只读已有表。
- Security/privacy: 电话仍仅 confirm 后解密；审计日志保留。
- Compatibility/versioning: 小程序兼容现有 API。
- Rollback: 回退小程序页面即可。
